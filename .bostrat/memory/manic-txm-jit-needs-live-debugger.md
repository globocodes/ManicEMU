**Facts:** The "occasional crash when starting a game" (Shrek 2, 2026-10-16 23:42) is Dolphin's JIT ARM64 executing the first block of its code buffer and the kernel refusing it as unsigned code. The app had been running 6.5 min (launched 23:36:05, StikDebug attached then); by game start StikDebug had been suspended/killed, so no debugger was attached, but `jit_available()` (RetroArch fork `pkg/apple/JITSupport.m`) returned true from the sticky `CS_DEBUGGED` flag ("is currently OR HAS PREVIOUSLY been debugged"). On TXM hardware (iOS 26 on A15/M2 or newer, `codeSigningMonitor = 2` in the report) unsigned pages execute only while a debugger is attached and the cores ask StikDebug (brk + universal.js) to make each JIT region executable; with no debugger the app's SIGTRAP handler (`JIT26BreakpointHandler`, UniversalScript.swift) skips the brk silently, so the region never becomes executable → SIGBUS. On PPL hardware CS_DEBUGGED alone keeps JIT working after detach. A relaunch (StikDebug re-attaches) works, which is why it looked random.

**Fix (Track 2a2d9596):** RetroArch fork globocodes/RetroArch branch `game-start-crash` (3bf884a8, on top of controller-latency 15a03c96): `jit_available()` on TXM also requires a live tracer (`sysctl KERN_PROC` → `p_flag & P_TRACED`); new `jit_debugger_detached()` / `+[LibretroCore JITDebuggerDetached]`. App: Libretro pin → 3bf884a8, `PlayViewController.noteJITLostIfNeeded()` toasts "JIT is off for this session: StikDebug is no longer attached…" (string `JITDebuggerDetached` in every lproj) and the session runs the interpreter. Unbuilt on the Pi (no Xcode); CI build-sideload.yml builds it. Second crash fixed alongside: `ObjectUpdatable.change` joins an open Realm write instead of nesting one (PlatformSelectionView called `ensureDolphinGameID()` inside `Game.change` → RLMException on platform change of GC/Wii games without a cached id).

**How to apply:** when JIT "randomly" fails or crashes on the iPad, first ask whether StikDebug is still alive; keep StikDebug/LocalDevVPN resident before long sessions. Any new JIT-availability check must use `LibretroCore.jitAvailable()` (now live-aware), never raw CS_DEBUGGED. The installed app comes from `build/ac-events` (= main + jit-spike + AC events) — merge main there after the PR lands or the fix never reaches the iPad.

**Status 2026-10-19:** verified on the iPad Air M4 (iPadOS 26.5.2) with build 0a1f288a of build/ac-events (ManicEMU PR #4 merged): a GameCube start minutes after StikDebug was suspended runs on the interpreter with the "JIT is off for this session" toast instead of crashing.
