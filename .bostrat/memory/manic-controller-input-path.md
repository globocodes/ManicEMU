**Facts:** Physical controllers reach libretro cores through DeltaCore, not RetroArch's `mfi_joypad.m` (that driver is compiled but Manic uses `manic_joypad.m`, whose poll is empty and whose per-port arrays are written by `manic_input_button_event` / `manic_input_analog_event`). Chain: `MFiGameController` sets `GCController.handlerQueue = ExternalInputDispatch.queue` (off-main, qos userInteractive), per-axis `valueChangedHandler` → deactivate opposite direction + activate direction with value → `GameControllerStateManager` → `ExternalInputDispatch.deliverActivate`; continuous (stick) inputs go through `AnalogInputCoalescer`, which keeps the last sample per (controller, receiver, input) and flushes them with ONE `DispatchQueue.main.async` per run-loop pass, iterating a Swift Dictionary (unordered). Receivers (`PlayViewController.updateExternalGameController`) = the play VC and the emulator core; the core calls `NGCEmulatorBridge.shared.activateInput(_:value:playerIndex:)`, which keeps ONE `leftThumbstickPosition`/`rightThumbstickPosition` CGPoint for ALL players and sends `LibretroCore.moveStick(isLeft, x, y, playerIndex)` → `manic_axes[port][0..3]`. RetroArch's `runloop_iterate` (Dolphin frame) runs on the MAIN thread from a CADisplayLink (`cocoa_common.m step:`), so every stick sample waits for the current emulator frame. Upstream Manic-EMU main has the same shared-position code; Wii/N64/PS1/DOS/Arcade/Amiga/C64 bridges share the pattern. Observability on the installed `jit-spike` build: every Dolphin launch writes a RetroArch INFO log to `Documents/Netplay Logs/` and one line to `Manic MP sessions.log` (CPU core, clock, JIT); frame-time stats (`[Netplay] Stats:` line) exist only inside a connected lockstep netplay session; nothing records input events, their timestamps, or GameController `lastEventLatency`; `Log.debug` is DEBUG-only; `audio_latency` is set to 200 ms at launch.

**Why:** operator saw both controllers "cut out" in Mario Party 4 two-player play when both sticks moved at once (Track 84fa4dbd, 2026-10-02). The shared position means P2's axis write is sent together with P1's stale other axis, and a release by one player zeroes a component for the other; the unordered flush can deliver activate(right) before deactivate(left) from one HID report, leaving the stick at 0 while held.

**How to apply:** fix stick cross-talk in the app bridges (per-player positions, e.g. `[Int: CGPoint]`) and make the coalescer flush ordered (array/sequence number, or merge opposite-direction pairs into one axis event); add input timing (per-controller `GCPhysicalInputProfile.lastEventTimestamp`/`lastEventLatency`, hop time to main, frame time) to the session log before judging the iPad "too slow". Submodules: read DeltaCore and RetroArch by fetching the sha pinned in `git ls-tree origin/jit-spike Dependencies/<name>`.
